# Privacy design

PrivacySpec must not create a new sensitive-data artifact while observing application behavior.
Data minimisation is an architectural boundary, not an output formatting preference.

## Data lifecycle

High-confidence browser input values are captured into bounded, test-scoped registries. Network,
console, and storage sink material is also retained only in bounded browser/test-worker memory.
Correlation derives semantic flows and then clears the transient registries during fixture
teardown.

```text
browser/test-worker memory -> deterministic correlation -> sanitized semantics -> disposal
```

The implementation does not use a stable raw-value hash for baseline identity. Exact, encoded,
Base64, and SHA-256 representations are generated transiently only to find a match.

## Persisted data

PrivacySpec attachments, latest-run handoffs, baselines, terminal output, and JSON reports may
contain:

- data category and source confidence;
- sink kind and structured field location;
- recipient origin/host and first-party classification;
- normalized endpoint and deterministic transform class;
- Playwright test file, title, and project in occurrence evidence;
- rule ID, technical-control references, and regulatory relevance;
- aggregate counts, diagnostics, and timing.

They must not contain raw input values, request bodies, console arguments, storage values,
passwords, tokens, or screenshots/traces generated by PrivacySpec. Baselines additionally exclude
test identity and contain only stable semantic review identities.

Runtime JSON artifacts and baselines are written atomically with mode `0600`. Default runtime paths
are ignored by Git. Users remain responsible for protecting CI artifacts and for avoiding other
Playwright reporters, traces, screenshots, or application logs that may independently retain test
state.

## Processing boundary

All processing is local. PrivacySpec has no telemetry, hosted backend, user account, network
lookup, or AI dependency. Static regulatory/control mappings are shipped with the package.

## Safety bounds

Source counts and value sizes, sink entries and retained bytes, request body size, console
serialization, URL/path length, correlation comparisons/bytes, and output flow counts are bounded.
Reaching a bound produces a sanitized informational diagnostic and makes the run ineligible for a
baseline update rather than silently presenting incomplete evidence as complete.

## Known limits

PrivacySpec cannot observe backend-to-backend transfers after a browser request completes. It does
not inspect response bodies, arbitrary JavaScript transformations, WebSocket payloads, deep service
worker behavior, or IndexedDB. It deliberately classifies only strong email,
telephone, and password controls; unclassified data should not be interpreted as absent.

Application code and unrelated Playwright tooling can still persist test data. Playwright's own
error-context artifacts can retain entered form state, so privacy-safe
evaluation should disable unnecessary traces/screenshots/error-context copying and use generated,
non-production data.
